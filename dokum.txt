BAB 02
ANALISIS SISTEM
 
2.1 Analisis Kebutuhan 
Analisis kebutuhan dilakukan untuk memetakan spesifikasi minimum perangkat serta fitur apa saja yang wajib disediakan oleh sistem agar aplikasi dapat berjalan optimal.
2.1.1 Kebutuhan Fungsional 
Kebutuhan fungsional mendefinisikan fitur-fitur utama dan proses manipulasi data yang dapat dilakukan di dalam sistem InstaWeb:
Sistem Autentikasi: Sistem wajib memiliki fitur Login, Register, dan Logout untuk membedakan dan mengamankan hak akses antar pengguna.
Manajemen Data (CRUD): Sistem harus mampu melakukan proses pembuatan (Create), pembacaan (Read), pengubahan (Update), dan penghapusan (Delete) data konten atau data pengguna di dalam website secara langsung.
Perutean Halaman (Routing): Sistem backend harus mampu mengalihkan pengguna ke halaman dashboard utama setelah proses autentikasi berhasil.
 
2.1.2 Kebutuhan Non-Fungsional
Kebutuhan non-fungsional berfokus pada kualitas perilaku dan kinerja dari sistem yang dibangun:
Aplikasi Mudah Digunakan (Usability): Antarmuka didesain bersih dan minimalis agar pengguna awam dapat memilih dan merakit template tanpa kebingungan.
Performa Kecepatan: Waktu tunggu pemuatan halaman (page load time) website diusahakan tidak lebih dari 5 detik pada kondisi jaringan internet stabil.
Keamanan Data: Informasi sensitif seperti kata sandi (password) pengguna tidak boleh disimpan dalam bentuk teks biasa, melainkan wajib melalui proses enkripsi atau penyamaran (hashing) pada database backend.
Tampilan Menarik dan Konsisten: Penerapan tema CSS yang serasi di seluruh halaman aplikasi, memastikan kenyamanan visual yang berkelanjutan.


 








2.2 Pengguna Sistem
Aplikasi website InstaWeb melibatkan dua level pengguna dengan hak akses yang berbeda, yaitu:
Administrator (Admin): Memiliki otoritas tertinggi untuk mengelola keseluruhan website, memantau data pengguna terdaftar, serta melakukan konfigurasi database server.
Pengguna Umum (User): Memiliki hak akses terbatas untuk melakukan pendaftaran akun, login ke sistem, serta mengelola data atau konten pribadi mereka masing-masing tanpa bisa mengintervensi data pengguna lain.

3.1 Use Case Diagram (Gambaran Umum)
Use Case Diagram menggambarkan interaksi antara aktor (pengguna) dengan sistem InstaWeb. Terdapat tiga aktor utama dalam sistem ini:
1. Pengguna Umum (User Owner): Aktor yang memiliki hak penuh atas halaman yang dibuatnya, termasuk berlangganan paket premium dan mengundang kolaborator.
2. Kolaborator (Collaborator): Aktor yang diundang oleh owner untuk membantu menyunting komponen halaman di dalam builder, dengan hak akses terbatas (tidak bisa menghapus halaman atau mengelola langganan).
3. Administrator (Admin): Aktor yang mengelola keseluruhan sistem, melihat ringkasan pendapatan, statistik global, dan dapat mengesampingkan status langganan pengguna.

Berikut adalah hubungan aktor dengan use case di dalam sistem:

A. Aktor: Pengguna Umum (User Owner)
   - Melakukan Registrasi Akun
   - Melakukan Login / Logout
   - Mengelola Halaman (Create, Read, Update, Delete Page)
   - Mengakses Builder (Menambah, Menghapus, dan Mengatur Posisi Section)
   - Memodifikasi Data Section (Menyunting Teks, Mengunggah Gambar)
   - Mengatur Konfigurasi SEO (Meta Title, Meta Description, Open Graph Image)
   - Membeli Paket Langganan Premium (Plus / Pro+) via Midtrans Snap Payment
   - Melihat Analitik & Statistik (Melihat grafik harian, persentase rujukan, dan log pengunjung)
   - Mengundang Kolaborator via Email (Khusus Paket Pro+)
   - Mengunduh / Ekspor Halaman ke File HTML Standalone (Khusus Paket Pro+)
   - Mengelola Kotak Masuk (Inbox) Undangan Kolaborasi dari Pengguna Lain

B. Aktor: Kolaborator
   - Melakukan Login / Logout
   - Mengakses Kotak Masuk (Inbox) untuk Menerima / Menolak Undangan Kolaborasi
   - Mengakses Builder Halaman yang Dibagikan (Edit, Urutkan, Tambah Section)
   - Melihat Statistik Analitik Halaman yang Dibagikan

C. Aktor: Administrator
   - Melakukan Login / Logout
   - Memantau Statistik Penggunaan Global (Jumlah Pengguna, Halaman, Views)
   - Melihat Ringkasan Pendapatan & Berlangganan Aktif
   - Memperbarui Paket Langganan Pengguna Secara Manual

3.2 ERD (Entity Relationship Diagram)
ERD InstaWeb mendefinisikan hubungan antar tabel data relasional di dalam basis data SQLite. Sistem ini memiliki 10 entitas utama:

1. User (users): Menyimpan profil dasar pengguna.
   - Relasi: One-to-Many ke Page (Satu user dapat memiliki banyak halaman).
   - Relasi: One-to-One ke Subscription (Satu user memiliki maksimal satu status langganan).
   - Relasi: One-to-Many ke PageCollaborator & Invitation (Sebagai kolaborator atau penerima).

2. Page (pages): Menyimpan meta data halaman website.
   - Relasi: Many-to-One ke User (Setiap halaman dimiliki oleh satu user).
   - Relasi: One-to-Many ke PageSection (Satu halaman memiliki banyak bagian/sections).
   - Relasi: One-to-Many ke PageView (Satu halaman merekam banyak kunjungan).
   - Relasi: One-to-Many ke PageCollaborator & Invitation (Satu halaman memiliki banyak kolaborator).

3. Template (templates): Menyimpan jenis-jenis section modular yang tersedia (misal: Hero, Features, Testimonials).
   - Relasi: One-to-Many ke TemplateField (Satu template mendefinisikan banyak field input).
   - Relasi: One-to-Many ke PageSection (Satu jenis template dapat dipasang di banyak halaman).

4. TemplateField (template_fields): Menyimpan field input spesifik untuk setiap template (misal: title, image, button_text).
   - Relasi: Many-to-One ke Template.
   - Relasi: One-to-Many ke SectionFieldValue (Satu field mendefinisikan banyak nilai tersimpan).

5. PageSection (page_sections): Menyimpan instansi template yang terpasang di suatu halaman beserta nomor urutnya (position).
   - Relasi: Many-to-One ke Page & Many-to-One ke Template.
   - Relasi: One-to-Many ke SectionFieldValue (Satu instansi bagian menyimpan banyak nilai data).

6. SectionFieldValue (section_field_values): Menyimpan nilai masukan riil dari pengguna untuk setiap field section.
   - Relasi: Many-to-One ke PageSection & Many-to-One ke TemplateField.

7. PageView (page_views): Merekam statistik kunjungan publik secara anonim.
   - Relasi: Many-to-One ke Page.

8. Subscription (subscriptions): Menyimpan status transaksi dan tipe paket SaaS (Free, Plus, Pro+).
   - Relasi: One-to-One ke User.

9. PageCollaborator (page_collaborators): Menyimpan daftar pengguna yang sah untuk membantu mengedit halaman milik orang lain.
   - Relasi: Many-to-One ke Page & Many-to-One ke User.

10. Invitation (invitations): Menyimpan riwayat dan draf undangan kolaborasi antar pengguna.
    - Relasi: Many-to-One ke Page, User (Sender), dan User (Recipient).

IMPLEMENTASI
 
4.1 Lingkungan Pengembangan 
Dalam proses membangun dan mengeksekusi kode program InstaWeb, lingkungan perangkat keras dan perangkat lunak yang digunakan tim meliputi:
Sistem Operasi: Windows 10/11 Home/Pro 64-bit.
Text Editor / IDE: Visual Studio Code (VS Code) dengan ekstensi Python terinstal.
Penyimpanan Proyek: Direktori lokal pada komputer pengembang.
Web Browser Utama: Google Chrome dan Mozilla Firefox (digunakan untuk memantau konsol eror javascript dan responsivitas desain).
 
4.2 FRAMEWORK 
Aplikasi InstaWeb dikembangkan dengan memanfaatkan kemampuan framework web mikro berbasis Python, yaitu Flask. Framework ini bertanggung jawab penuh dalam menangani routing (perutean URL), menerima atau merespons HTTP Request (GET & POST), serta merender data ke berkas tampilan HTML.


4.3 Bahasa Pemrograman
Teknologi yang dikombinasikan dalam pembuatan aplikasi web ini mencakup:
Python: Bahasa inti di sisi server (backend) untuk memproses logika bisnis aplikasi, melakukan enkripsi data, dan menjembatani komunikasi ke database.
HTML5: Digunakan untuk menyusun struktur elemen statis, tabel, serta form masukan data pada halaman web.
CSS3 & Bootstrap: Digunakan untuk mengatur tata letak komponen, visualisasi tombol, warna tema, serta memastikan aspek responsive layout bekerja dengan baik.
JavaScript: Digunakan untuk memberikan interaksi asinkronus ringan di sisi pengguna.

BAB 05
PENGUJIAN SISTEM
 
5.1 Metode Pengujian
Pengujian sistem pada aplikasi InstaWeb dilakukan dengan menggunakan metode Black Box Testing (Pengujian Kotak Black Box). Metode ini berfokus sepenuhnya pada pengujian fungsionalitas luar aplikasi dengan cara menguji masukan (input) dan memvalidasi apakah keluaran (output) yang dihasilkan sudah sesuai dengan skenario rancangan, tanpa perlu menguji baris kode internalnya secara mendalam.  	

5.2 Skenario Pengujian 
Rencana pengujian dirancang lewat beberapa skenario pengujian fungsional penting berikut:
Pengujian Fitur Registrasi: Mengisi form pendaftaran dengan email baru dan menguji validasi jika password terlalu pendek.
Pengujian Fitur Login: Memasukkan kombinasi username dan kata sandi, baik dengan parameter data yang benar maupun data acak (salah).
Pengujian Fitur CRUD Konten: Melakukan penambahan data baru, memperbarui teks data, serta menghapus data melalui tombol yang tersedia pada dashboard.

 6.2 Saran
Meskipun aplikasi ini sudah berfungsi sesuai kebutuhan dasar tugas akhir kelas X SIJA, tim menyadari masih terdapat ruang peningkatan kualitas yang bisa diterapkan pada pengembangan selanjutnya:
Pengembangan Fitur Keamanan: Menambahkan fitur verifikasi CAPTCHA pada form login guna menghindari ancaman serangan siber berupa pembongkaran paksa kata sandi (brute-force attacks).
Optimalisasi UI/UX: Memperbanyak penggunaan animasi transisi elemen yang halus serta menyediakan opsi mode gelap (Dark Mode) untuk meningkatkan kenyamanan visual pengguna.
Migrasi Database: Mengupgrade sistem pangkalan data lokal dari yang awalnya bertipe file lokal mikro (seperti SQLite) ke server database relasional skala besar (seperti MySQL atau PostgreSQL) apabila volume data pengguna di masa mendatang terus bertambah.
